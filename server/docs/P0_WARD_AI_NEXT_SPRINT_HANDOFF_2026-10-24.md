## Antigravity AI request sequence — Free text only

The Frontend `/ai/chat` call does **not** exist on this Backend. The one public floating popup should use these endpoints, with no fake success state:

1. `POST /ai/guest-sessions`, no auth/body → **201** `{id:UUID,token:string,expiresAt:ISO8601}`. Keep token only in session memory. If a valid guest token is already in memory, reuse it. A registered user instead uses their existing `Authorization: Bearer <access-token>` and skips guest creation.
2. Send either `X-Findwork-Guest-Token: <token>` **or** the user Bearer header on every following call. `GET /ai/conversations` → **200** array of up to 30 owned `{id,createdAt,updatedAt}`. Reuse an owned conversation ID from that list, or `POST /ai/conversations` with no body → **201** `{id,createdAt,updatedAt}`.
3. `POST /ai/conversations/:id/messages`, `Content-Type: application/json`, body `{"content":"How should I prepare for an interview?"}` → provider success **201** `{user:{id,role:"USER",content,createdAt},assistant:{id,role:"ASSISTANT",content,createdAt},usage:{totalTokens,estimatedCostMicros}}`. Render only `assistant.content` after the successful HTTP response. A provider failure saves neither message.
4. `GET /ai/conversations/:id/messages` → **200** up to 100 owned messages, ordered oldest first. A foreign conversation returns **404** `AI_CONVERSATION_NOT_FOUND`; missing/expired auth returns **401** `AI_AUTH_REQUIRED`. `DELETE /ai/conversations/:id` → **200** `{id,deleted:true}` for an owned conversation.
5. A guest session expires 24 hours after creation. On 401, clear the in-memory token, request a new guest session and start a new conversation. Do not claim old guest history is recoverable under the new token. Guest session issuance is limited to three per direct IP per 24 hours, plus 5 per 10 minutes; message sending is throttled and daily token/request/cost limits apply. Show HTTP 429 codes `AI_GUEST_SESSION_LIMIT`, `AI_CONVERSATION_LIMIT`, `AI_DAILY_BUDGET_EXCEEDED` or `RATE_LIMITED` as limits with retry guidance, without automatic registration loops.

`POST /ai/conversations/:id/messages` also parses multipart `content` plus an `image` file (PNG/JPEG/WebP, at most 2 MiB); `POST /ai/transcriptions` parses multipart `file` (WAV, at most 2 MB/60 seconds) and would return `{text}` on real provider success. **Both are paid features.** The current source fails them closed with **403 `AI_PREMIUM_ENTITLEMENT_REQUIRED`** for every account until server-verified paid entitlements and quotas are implemented. The existing running 3002 process has not been restarted with this new gate, so do not infer the gate is live from source alone. Image/voice UI should remain locked and label the entitlement requirement. No AI mock interview endpoint currently exists.

Other text errors: 400 `AI_MESSAGE_INVALID`, `AI_MESSAGE_TOO_LARGE`, `AI_SENSITIVE_INPUT_BLOCKED`; 503 `AI_PROVIDER_NOT_CONFIGURED`, `AI_PROVIDER_AUTH_INVALID`, `AI_PROVIDER_RATE_LIMITED`, `AI_PROVIDER_UNAVAILABLE`, `AI_PROVIDER_TIMEOUT`, `AI_PROVIDER_REQUEST_REJECTED`, `AI_PROVIDER_RESPONSE_INVALID`. The latter status mapping is in the new source and needs a restart before live HTTP verification. Error JSON is `{code,message,details?,traceId,path,timestamp}`. Do not treat all 503 responses as missing credentials; display the actual `code`.
