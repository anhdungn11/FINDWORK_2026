# FINDWORK integrated Backend handoff — 2026-10-23

## Runtime and evidence

This release candidate combines Employer Workspace media/profile/location code with persistent account types. Backend `http://127.0.0.1:3002/api/v1` uses only PostgreSQL `127.0.0.1:5432/findwork_employer_media_3002/public`. Eight migrations are applied. The project's permission/reference foundation was initialized there; real HTTP acceptance created labeled test-owned accounts and companies. It passed profile update/reload, first headquarters location, PENDING legal request, logo and cover upload/reload/delete, and tenant denial. Port 5177 is reserved for a separate Frontend, but browser acceptance has not run. The demo at 3000/5176 and `findwork_dev`/`findwork_test` were not changed.

## Changed contracts for Antigravity

| Method and URL | Auth / request | Actual response | Errors |
| --- | --- | --- | --- |
| `POST /api/v1/auth/register/v2` | Public, allowed `Origin`, rate limited; JSON `{email,password,accountType:"CANDIDATE"|"EMPLOYER"}` | 201 `{accessToken,accessTokenExpiresInSeconds,user:{id,email,status,emailVerified,accountType}}`; HTTP-only refresh cookie | 400 `VALIDATION_ERROR` for missing/invalid type or DTO; 409 `AUTH_EMAIL_ALREADY_REGISTERED`; 429 `RATE_LIMITED` |
| `POST /api/v1/auth/register` | Same body and behavior; existing URL retained | Same 201 response | Omitted account type now **400** `VALIDATION_ERROR`. This is a deliberate request-contract change: new legacy accounts cannot be created. |
| `POST /api/v1/companies` | Bearer `EMPLOYER` or existing `LEGACY_UNCLASSIFIED`; explicit JSON `{name:string(2..255),slug:lowercase-kebab-case(3..220)}` | 201 `{id,name,slug,status:"ACTIVE",verificationStatus:"UNVERIFIED",createdAt}`; creates OWNER membership and company roles transactionally | 401 auth; 403 `AUTH_ACCOUNT_TYPE_FORBIDDEN` for `CANDIDATE`; 409 slug conflict |
| `PUT /api/v1/companies/:companyId/media/:kind` | Bearer active member with `company.update:COMPANY`; `kind=logo|cover`; multipart field `file`; PNG/JPEG/WebP | 200 `{kind,available:true}` | 400 invalid kind/file/type/size/dimensions; 401 auth; 403 company RBAC; 413 transport cap; 503 storage unavailable |
| `GET /api/v1/companies/:companyId/media/:kind` | Public GET, active company | 200 raw image bytes, matching `Content-Type`, `Cache-Control:no-store`, `X-Content-Type-Options:nosniff` | 404 absent company/media; 503 storage or asset unavailable |
| `DELETE /api/v1/companies/:companyId/media/:kind` | Same Bearer permission as PUT | 200 `{kind,available:false}` | 401/403 auth/RBAC; 400 invalid kind; 503 storage unavailable |

For media display, use the GET URL directly as an `<img src>`, add a cache-busting query after a successful PUT, and use the stable URL again after page reload. Do not send internal asset keys. Clear the Frontend API client's default JSON `Content-Type` for `FormData` and let the browser/Axios adapter supply the multipart boundary. The Backend validates MIME against bytes, enforces 1 MiB/2048 px for logo and 2 MiB/4096 px for cover, and stores files in the configured private directory. The exact examples and full error list are in [EMPLOYER_MEDIA_INTEGRATION_HANDOFF.md](EMPLOYER_MEDIA_INTEGRATION_HANDOFF.md).

`GET /api/v1/auth/me`, login and refresh report the persisted `user.accountType`; old NULL users report `LEGACY_UNCLASSIFIED` and retain current memberships. Candidate APIs require `CANDIDATE` or existing legacy status. Employer writes still require active membership and scoped permission. A CANDIDATE cannot gain company management through authentication alone. `GET /api/v1/jobs` remains public and creates no CandidateProfile. No navigation GET creates a Company or membership. See [ACCOUNT_TYPE_API_HANDOFF.md](ACCOUNT_TYPE_API_HANDOFF.md) for the full authorization matrix.

## Existing Employer and recruitment APIs

`GET/PATCH /api/v1/companies/:companyId/profile` require `company.view/update:COMPANY`. PATCH accepts a nonempty subset of `{name,legalName,taxCode,industryId,description,website,employeeSizeRange,foundedYear}`; status, verification, slug and media keys are excluded. Profile GET returns those fields plus `id,slug,industry,logoAssetKey,coverAssetKey,verificationStatus,verifiedAt,status,createdAt,updatedAt` to authorized members only. Public company reads keep their safe field selection. `POST /api/v1/companies/:companyId/verification-request` requires `company.update:COMPANY`; it never sets VERIFIED itself. Admin review remains a separate permissioned endpoint.

`GET/POST /api/v1/companies/:companyId/locations`, `GET/PATCH/DELETE .../locations/:locationId`, and `PUT .../locations/:locationId/headquarters` remain available with `company.view/update:COMPANY`. Create accepts `{countryCode?,provinceId?,wardId?,addressLine?}` with at least an address line or province, and the first location becomes headquarters. A ward must belong to the chosen active province. Member, invitation, Job, application and admin routes keep the contracts in [SUBMISSION_BACKEND_MVP_API.md](SUBMISSION_BACKEND_MVP_API.md); no new role grants were made. `HIRING_MANAGER` and `VIEWER` were not widened.

## Remaining gates

The 2026 reference release contains a verified 34-province snapshot and 67 skills/30 certificates, but no complete verified ward dataset. The isolated database currently has no province, ward, skill or certificate rows because only the project foundation seed was run. Importing a 7-step draft that references those catalogs returns `503 CANDIDATE_REFERENCE_CATALOG_UNAVAILABLE`; an invalid code in a populated catalog returns `400 CANDIDATE_REFERENCE_INVALID`. The previously reported draft codes 38 and 16531 have official 2025 evidence for Thanh Hóa and the new Phường Sầm Sơn in [Decision 19/2025/QĐ-TTg](https://vanban.chinhphu.vn/?classid=1&docid=214409&orggroupid=3&pageid=27160), but current 2026 ward status must be reconciled against the [National Statistics Office register](https://danhmuchanhchinh.nso.gov.vn/Lich_Su_Moi.aspx) before import. Import also requires the latest draft `version`, `confirmPrivacy:true`, and separate explicit `confirmPrivacyDifferences:true` and/or `confirmOmitUnsupportedAssets:true` when relevant. Do not rewrite a saved draft, infer ward mappings or weaken privacy. See [candidate-import-contract.md](candidate-import-contract.md). The current reference-release seed is hard-gated to `findwork_dev` with a backup gate and was deliberately not run here.

AI/chat, operational interview scheduling, meeting creation, recording and transcript APIs are not implemented. Existing Interview/Participant tables and permission codes are only a foundation; provider credentials, approved role grants, consent policy and additive schema changes remain dependencies. See [AI_BACKEND_FOUNDATION_PROPOSAL.md](AI_BACKEND_FOUNDATION_PROPOSAL.md).
