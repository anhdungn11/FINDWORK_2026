# Backend release readiness (2026-10-20)

This is an operational checklist for the current Backend code, not evidence of PostgreSQL E2E execution.

1. Set `NODE_ENV=production`, a dedicated PostgreSQL `DATABASE_URL`, `API_PREFIX=api/v1`, `JWT_ACCESS_SECRET` and a different `REFRESH_TOKEN_PEPPER` (at least 32 characters each). Set `CORS_ORIGINS` explicitly to the HTTPS Frontend origin; production startup now rejects a missing or HTTP origin. Serve the API over HTTPS so Secure refresh cookies can work. Keep the test and development databases separate from production.
2. Apply checked-in Prisma migrations in the approved target, then provision the permission registry and existing baseline roles through an approved procedure. The existing global seed also writes reference data and synchronizes unrelated roles; do not use it as the narrow Admin grant operation. Run `npm run admin:grants -- --dry-run` against local `findwork_test` to review the two proposed roles. The scoped command intentionally refuses production and never assigns user accounts. Production role provisioning and named staff assignments need separate approval and an audited procedure.
3. To enable Company invitations, configure `EMAIL_DELIVERY_MODE=resend`, `EMAIL_INVITATION_DELIVERY_ENABLED=true`, `EMAIL_ACTIVE_KEY_ID`, `EMAIL_KEYRING_JSON`, `EMAIL_RESEND_API_KEY`, `EMAIL_FROM`, and an HTTPS `EMAIL_INVITATION_URL`. Start the separate invitation email worker. If disabled or incomplete, `POST /companies/:companyId/invitations` returns 503 and creates no invitation. The default remains disabled. Verification email has its own `EMAIL_VERIFY_URL` and worker switch.
4. Existing CI in `.github/workflows/backend-ci.yml` checks Prisma generation/validation, migrations and seed on an ephemeral `findwork_test`, build, then serial Jest integration. Local unit, TypeScript and build checks do not establish PostgreSQL Company/Admin E2E success. The Company/Admin fixture tests remain unexecuted until separate authorization for setup, writes and cleanup.
